# 行走的坐标素材替换工作流

## 1. 工作流目标

### 1.1 固定素材记录

页面始终通过 `AssetRecord.id` 引用素材。占位版本与正式版本共享同一个固定 ID、目标宽高和页面用途，素材晋级只更新记录状态与交付路径。

### 1.2 公开仓库交付物

公开仓库保存：

- `data/assets.ts` 中的素材元数据与外部授权记录编号；
- `public/images/` 中的明确标识占位图；
- `public/media/` 中由脚本生成的 AVIF 与 WebP。

团队素材档案保存原始文件、授权书和人物同意记录。公开记录通过 `rightsRecordRef` 与该档案建立对应关系。

## 3. 入库信息

### 3.1 文件要求

原始图片的像素尺寸覆盖清单目标尺寸，宽高比偏差在 3% 以内。转换脚本以记录中的目标尺寸生成交付文件，并移除原始图片中的附加元数据。

### 3.2 内容信息

每条正式素材记录具备：

- 与画面内容一致的 `alt`；
- 署名 `credit`；
- `YYYY-MM-DD` 格式的 `captureDate`；
- 页面用途 `displayUse`；
- 使用范围 `usageScopes`。

### 3.3 权利信息

正式素材使用：

- `rightsStatus: "cleared"`；
- `consentStatus: "not-required"` 或 `"obtained"`；
- 可定位到团队外部档案的 `rightsRecordRef`；
- `reviewStatus: "reviewed"`。

## 4. 转换流程

### 4.1 执行命令

在仓库根目录执行：

```powershell
npm run assets:convert -- --id "outcome-01" --source "C:\素材\成果页截图.png"
```

脚本读取固定素材记录，检查源文件尺寸与宽高比，并生成：

- `/media/{id}.avif`；
- `/media/{id}.webp`；
- 宽度大于 480px 时生成 `/media/{id}-480.avif`；
- 宽度大于 480px 时生成 `/media/{id}-480.webp`。

### 4.2 人工画面审核

转换后核对：

1. 画面人物、地点与记录身份一致；
2. 主要主体位于页面裁切安全区；
3. 替代文本准确描述画面信息；
4. 署名、拍摄日期和用途与团队档案一致；
5. 人物授权与公开范围覆盖网站使用。

### 4.3 记录晋级

人工审核通过后，将 `data/assets.ts` 中对应记录更新为正式分支：

```ts
{
  id: "outcome-01",
  assetStatus: "ready",
  finalSrc: "/media/outcome-01.webp",
  reviewStatus: "reviewed",
  publicationStatus: "ready",
  rightsStatus: "cleared",
  consentStatus: "not-required",
  credit: "北京科技大学社会实践团队",
  captureDate: "2026-07-28",
  usageScopes: ["website"],
  rightsRecordRef: "团队素材档案中的记录编号",
}
```

其他基础字段继续沿用同一条固定素材记录。

## 5. 自动化门禁

### 5.1 素材检查

```powershell
npm run assets:check
```

该命令检查固定 ID、元数据、文件格式、目标尺寸、响应式版本、文件大小、授权状态和占位标识。

### 5.2 全仓库检查

```powershell
npm run check
npm run test:e2e
```

全仓库门禁同时检查数据完整性、未引用文件、无引用 CSS、内部链接、媒体懒加载、响应式布局、可访问性与视觉基线。

## 6. 回退流程

### 6.1 内容回退

当正式素材需要撤回时，对应 `AssetRecord` 恢复为 `placeholder` 或 `planned` 分支，并重新指向既有 `/images/{id}.svg`。页面继续使用相同 ID、宽高和组件结构。

### 6.2 文件回退

版本控制保留素材记录与交付文件的变更历史。回退提交后运行 `npm run assets:check`、`npm run check` 和 `npm run test:e2e`，确认占位版本重新成为公开输出。
