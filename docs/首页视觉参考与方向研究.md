# 《行走的坐标》首页视觉参考与方向研究

> 研究日期：2026-07-28
>
> 研究范围：首页视觉风格、电影感、路线表达、证据密度、静态内容悬停、页面分区、字体与尾部收束
>
> 文档定位：视觉方向参考，不替代正典设计规格与实施计划

## 1. 研究目标与边界

### 1.1 需要回答的核心问题

#### 1.1.1 电影感如何成立

首页的电影感应由决定性影像、镜头构图、叙事字幕、声音或克制的镜头运动共同建立。路线概念由章节、地点、日期和行动顺序表达，首屏不承担绘制路线图的任务。

#### 1.1.2 路线、地点与时间如何同时出现

首页需要让用户快速理解“三条路线、十三处地点、十四天实践”，但不把地图或时间轴强行塞入 Hero。真实地图继续承担路线页的空间理解；首页使用路线章节、地点清单、日期字幕和代表影像建立叙事顺序。

#### 1.1.3 页面如何提高信息与视觉密度

密度不等于堆字。目标是让每个主要屏幕同时出现两至三类有意义的信息，例如影像、说明、档案字段、图注、日期或下一步动作，减少只靠超大标题与纯色背景占据高度的区段。

#### 1.1.4 非点击内容如何获得悬停反馈

非点击卡片可以具有视觉反馈，但反馈应表达“正在观看这一组内容”，而不是“这里可以跳转”。适合采用细描边、局部渐变、编号强调或图像对比度变化；不采用整体抬升、明显阴影、指针光标或隐藏关键信息。

#### 1.1.5 页面如何形成展陈节奏

首页应像一场连续展陈：开场建立情绪，证据条确认事实，方法区展示工作，路线区展开章节，成果区形成交付，结尾完成收束。不同分区由内容材料和构图变化区分，而不只依赖大块背景色。

#### 1.1.6 字体如何服务纪实与档案

标题负责叙事力度，正文负责持续阅读，日期、坐标、编号与来源负责可信度。中文正文保持高可读无衬线；标题可使用更强字重；档案数字采用等宽或表格数字；衬线字体只在引语、章节题签等少量位置使用。

### 1.2 已确认的项目边界

#### 1.2.1 首页路线表达

最终首页以影像、章节编号、地点名称、日期范围和行动顺序表达路线，不使用当前的装饰性曲线与圆点。

#### 1.2.2 公开内容状态

公开版本按内容已经完成的观看语境设计。示意素材与替换状态属于内部预览和制作流程，不作为面向主要用户的视觉主题。

#### 1.2.3 研究方法说明

本研究优先使用机构或项目官方页面。标记为“视觉观察”的网站已在桌面视口中检查当前页面；标记为“结构核验”的网站因验证墙、地区网络或重型交互限制，仅依据其官方页面内容与公开结构归纳，不对未看到的具体动效作断言。

### 2.2 最值得直接借鉴的八个案例

#### 2.2.1 SBS《The Boat》

- 风格化特点：黑白手绘、环境声、连续滚动与局部动画共同形成强烈叙事世界。
- 对电影感的回答：先让观众进入一个具体场景，再开始说明；运动来自雨、海、人物与镜头，而不是界面装饰。
- 对本项目的启发：首页可使用 5–8 秒无声行动循环或一张动作明确的现场影像，以日期、地点和行动字幕建立纪录片开场。
- 需要避开的部分：进入前强制点击、依赖声音和持续重动画不适合直接复制；本项目首屏信息仍应默认可见。

#### 2.2.2 A24《Warfare》

- 风格化特点：单张全幅电影画面占据主导，片名、导演、年份与观看动作形成清楚的前后层。
- 对电影感的回答：电影感首先来自镜头本身，而不是复杂 UI。影像有明确人物、动作、环境和光线，界面只负责标题与字段。
- 对本项目的启发：Hero 应优先选择“队员正在进入、观察、拍摄或记录”的决定性画面；项目名称、路线数量和实践方式叠加其上或紧随其后。
- 需要避开的部分：商业电影页的信息量较低，不能直接承担项目证据与方法说明。

#### 2.2.3 Searchable Museum

- 风格化特点：深色展厅氛围、全宽场景图、主题型大卡片、清楚的展览/故事/资源分区。
- 对信息密度的回答：不是把所有信息缩小，而是让一张卡同时包含视觉对象、展览性质、主题数量、简介和进入动作。
- 对分区的回答：每个区段都有真实内容材料作为视觉中心，背景只负责建立环境。
- 对本项目的启发：路线章节可在同一构图中放置路线影像、日期、地点数、代表地点和摘要，而不是只有路线名称与大段留白。

#### 2.2.4 Closer to Johannes Vermeer

- 风格化特点：围绕一个高质量视觉对象展开，允许引导式讲述与自主探索并存。
- 对证据与沉浸的回答：沉浸不要求减少信息；高分辨率对象、讲解、比较和收藏动作可以在同一体验中共存。
- 对本项目的启发：现场照片既是视觉材料，也是可检查的实践证据。可用局部放大、图注、拍摄时间、地点和记录动作增强可信度。
- 需要避开的部分：本项目没有适合无限缩放的单件艺术品，不应把图片查看器做成首页主交互。

#### 2.2.5 Photogrammar

- 风格化特点：地图、照片网格、时间、摄影者、地点与档案字段共同组成浏览界面。
- 对路线表达的回答：地图承担真实空间关系，缩略图与元数据承担材料发现；两者各自有明确职责。
- 对证据密度的回答：连续缩略图、简短图注、地点、作者和日期比大面积装饰更能建立档案感。
- 对本项目的启发：首页的方法区可采用“接触印样/工作底片”式排列；路线页继续以真实在线地图处理坐标与顺序。

#### 2.2.6 Anne Frank House Timeline

- 风格化特点：重要年份作为一级节点，每年下面组织具体日期、地点、事件与人物材料。
- 对时间表达的回答：时间不是一根必须始终可见的装饰轴，而是可扫描的章节索引和事件字段。
- 对本项目的启发：首页可用路线编号与日期范围形成三个章节；地点卡使用“日期 + 地点 + 行动”三项短字段表达实践进程。
- 需要避开的部分：完整历史时间轴信息量过大，不适合照搬到首页。

#### 2.2.7 故宫博物院数字文物库

- 风格化特点：分类筛选、对象网格、藏品编号、标题和数量并列出现，中文信息密度高但层级稳定。
- 对档案可信度的回答：编号、分类和对象信息直接可见，视觉对象与字段始终绑定。
- 对字体与排版的回答：中文正文保持常规可读尺度，识别度主要来自色彩、分栏、图片比例和字段层级，而不是不断放大标题。
- 对本项目的启发：路线与成果区可提高字段密度；坐标、日期、地点序号和来源应贴近对应图片或条目。

#### 2.2.8 The Pudding 视觉论文

- 风格化特点：每篇文章根据主题建立独立视觉语言，图像、数据、文字和交互共同回答一个明确问题。
- 对信息密度的回答：先提出问题，再用一个视觉证据推进一小步；长页面通过连续论证而非重复卡片维持节奏。
- 对本项目的启发：首页的方法链应展示“寻访—采集—解码—传播”各自对应的材料和产出，使四个步骤成为有证据的叙事，而不是抽象口号。
- 需要避开的部分：项目首页需要统一品牌，不适合让每个区段完全改变视觉系统。

## 3. 这些网站对项目核心问题的共同回答

### 3.1 对“首页如何具有电影感”的回答

#### 3.1.1 共同模式

1. 先确定一个决定性视觉场景，再安排标题和界面。
2. 画面包含人物行动、环境尺度、方向或事件张力。
3. 动效来自镜头、环境、材料揭示或场景切换。
4. 字幕式信息保持短小，使用地点、日期、人物或动作建立纪录片语境。
5. 首屏之后立即出现事实或元数据，避免情绪与项目内容脱节。

#### 3.1.2 对《行走的坐标》的回答

Hero 推荐采用“现场行动影像 + 项目标题 + 一句实践说明 + 两个入口 + 简短事实条”。桌面端可使用横向决定性影像或无声短循环，移动端使用独立裁切。三条路线不在 Hero 中绘制，而在下方以三个连续电影章节出现。

### 3.2 对“路线元素如何表达”的回答

#### 3.2.1 首页

每条路线作为一个章节，包含：

- 路线编号与名称；
- 日期范围；
- 地点数量与三至五个代表地点；
- 一张代表影像；
- 一句历史主题与一句实践动作；
- 进入路线的明确链接。

三个章节可使用横向错位、交替图文或全幅影像分章，不需要用线将它们连接。

#### 3.2.2 路线页

真实在线地图承担经纬度、地点位置与寻访顺序；地点列表承担主要操作；地点档案承担证据阅读。地图连线仅表达已核定的地点顺序。

### 3.3 对“如何提高信息与视觉密度”的回答

#### 3.3.1 推荐材料组合

| 分区 | 同屏材料 |
|---|---|
| Hero | 行动影像、标题、短说明、事实字段、入口 |
| 实践方法 | 现场照片、档案局部、步骤标题、产出或证据 |
| 路线章节 | 路线影像、日期、地点名、地点数、实践摘要 |
| 成果区 | 成果截图、成果名称、格式、摘要、访问动作 |
| 结尾 | 团队工作影像、项目总结、两个主要动作 |

#### 3.3.2 版式节奏

推荐采用“全幅—密集—全幅—密集”的节奏：Hero 全幅场景之后接紧凑事实与方法证据；路线章节重新放大影像；成果区回到高密度条目；结尾使用较短的场景收束。

#### 3.3.3 首页事实条

事实条保留实践周期、路线数量、地点数量和记录方式四项。内容是否已经适合发布由内部发布门禁判断，不作为首页面向观众的第五项状态字段。

### 3.4 对“静态内容是否应有 hover”的回答

#### 3.4.1 推荐反馈

- 默认边框为低对比细线，悬停时出现局部蓝绿渐变或沿边缘移动的轻微高光；
- 编号、步骤名或小型元数据提高对比度；
- 图片可轻微提高明暗或清晰度；
- 过渡时间约 160–220ms；
- `prefers-reduced-motion: reduce` 下即时切换颜色。

#### 3.4.2 语义限制

非点击内容保持默认光标，不整体上浮，不增加明显投影，不在悬停后才显示关键信息。可点击卡片才使用箭头位移、图片缩放或更强颜色变化。触屏端默认状态应已经完整，不依赖 hover。

### 3.5 对“分区与尾部如何优化”的回答

#### 3.5.1 分区

每个主要分区至少拥有一种专属材料：Hero 的行动影像、方法区的工作细节、路线区的地点影像、成果区的真实界面或文件、结尾的团队成果场景。分区差异主要来自材料比例、图文方向和明暗关系。

#### 3.5.2 尾部

结尾行动区控制在一个紧凑视口以内；桌面页脚建议约 120–180px 高，只保留品牌、组织归属、年份、必要链接和返回顶部。页脚不再承担第二个大面积视觉高潮。

### 3.6 对“字体系统如何调整”的回答

#### 3.6.1 推荐层级

- 叙事标题：高字重中文无衬线，减少过度换行；
- 正文与说明：400–500 字重，保持连续阅读；
- 引语或章节题签：可少量使用中文衬线；
- 坐标、日期、路线编号、档案编号：等宽或表格数字；
- 英文大写：只用于真实字段或小型分类，不作为大面积装饰水印。

#### 3.6.2 推荐效果

字体不承担全部风格化任务。项目气质主要由真实影像、档案字段、图注、章节结构和色彩关系形成，字体负责稳定、庄重与可读。

## 4. 建议形成的首页方向

### 4.1 方向名称

#### 4.1.1 电影纪实开场 + 档案展陈主体

这是当前最适合《行走的坐标》的组合方向：

- 开场借鉴《The Boat》与 A24，以决定性现场影像建立情绪；
- 展览层级借鉴 Searchable Museum，让每个章节包含可扫描事实；
- 路线与时间借鉴 Photogrammar 和 Anne Frank Timeline，使用真实地图、章节与字段各司其职；
- 档案密度借鉴故宫数字文物库；
- 方法叙事借鉴 The Pudding，让每一步都有对应材料。

### 4.2 建议页面顺序

#### 4.2.1 首页叙事链

1. 电影纪实 Hero；
2. 紧凑项目事实条；
3. 有材料支撑的四步实践链；
4. 三条路线电影章节；
5. 成果与档案条目；
6. 团队成果场景与结尾行动；
7. 紧凑页脚。

### 4.3 视觉关键词

#### 4.3.1 正向关键词

现场、行动、证据、章节、档案、字幕、接触印样、时间标记、地点字段、青年视角、真实尺度。

#### 4.3.2 风格控制

整体保持庄重、可信、青年化。红、黑与米白继续构成品牌基础；蓝绿仅用于内部示意素材或非常克制的交互边缘反馈，不成为新的主品牌色。

## 5. 素材与制作工作流

### 5.1 首页必需素材

#### 5.1.1 现有清单

正典设计文档已经定义 H01–H05、三条路线封面与 V02 首页短循环。进入首页重做前，应先完成以下最小素材包：

| 优先级 | 素材 | 用途 |
|---|---|---|
| P0 | H01 Hero 主影像 | 决定性开场 |

### 5.2 素材核定流程

#### 5.2.1 工作步骤

1. 团队按素材清单提交原片与元信息；
2. 先制作桌面与移动端接触印样，比较构图和裁切；
3. 选定主画面后核验人物同意、署名、拍摄日期、用途与授权范围；
4. 输出桌面、移动端和分享图所需版本；
5. 进行亮度、文字安全区、首屏加载和低网速测试；
6. 正式构建只引用核定素材，内部预览继续保留示意素材替换能力。

### 5.3 当前缺失项的处理

#### 5.3.1 无 V02 视频时

使用 H01 高质量静帧，配合轻微遮罩、短淡入和字幕出现即可。电影感不以视频为硬条件。

#### 5.3.2 无完整路线影像时

优先保证每条路线一张真实代表影像；地点数量、日期与代表地点由文字字段补齐。首页不使用与路线无关的通用历史图片代替现场材料。

## 6. 下一步决策

### 6.1 需要项目方核定的内容

#### 6.1.1 方向核定

确认“电影纪实开场 + 档案展陈主体”为首页下一轮设计方向。

#### 6.1.2 Hero 素材路径

在以下两种可落地路径中选择：

1. 先用 H01 静态主影像完成设计和响应式；
2. 同时准备 V02 无声短循环，并以 H01 作为封面和降级版本。

### 6.2 核定后的工作

#### 6.2.1 文档与实现顺序

1. 更新正典设计文档中的首页目标状态；
2. 明确 Hero、实践链、路线章节、成果区与结尾的线框；
3. 补齐或确认 P0 素材；
4. 实现桌面与移动端；
5. 完成自动化验证；
6. 由项目方进行真实页面验收；
7. 达到稳定状态后再进入三类真实使用测试。
